# Решение владельца до утверждения исправляет план

`friday decide` до утверждения только записывал решение. Исполнитель получал его как
`owner_decisions` вместе со старыми шагами вехи: решение «новый роут не вводим» и шаг
«создать новый роут» в одном задании. Дешёвый исполнитель такое противоречие не
разрешает. Вывод «Переоткрыты: m3» для вехи, которая ещё не исполнялась, обещал то,
чего не было. Исправление плана было только у процесса проекта (ADR 0015).

Решение: пока план Friday ждёт утверждения, `decide` передаёт текст решения
планировщику в новой сессии (`plan.revise`: исходный промпт, текущий план и что
изменить, без повторного чтения репозитория).

- **Границы.** Вехи из `--reopen` планировщик переписывает, остальные Friday возвращает
  в план из прежней ревизии, что бы ни ответила модель; веху вне решения нельзя и
  убрать. Без `--reopen` затронутые вехи выбирает планировщик, а Friday называет их по
  разнице ревизий.
- **Проверки.** Исправленный план проходит те же проверки выполнимости. Другая модель
  проверяет только изменённые вехи: весь план она получает как контекст, тексты файлов —
  только этих вех. План без изменённых вех на проверку не идёт. Замечания прежней
  проверки по нетронутым вехам остаются.
- **Сбой.** Если исправление не прошло, прежний план остаётся и ждёт утверждения;
  решение записано, повтор того же `decide` его не дублирует.
- **Вывод.** `decide` называет отдельно вехи, исправленные в плане, переоткрытые для
  повторного исполнения и те, которым решение только добавлено в контекст.
  Переоткрытой считается только выполненная веха.
- **Ревизии.** Предыдущая ревизия плана хранится в карточке (`plan-previous.json`),
  `friday plan KEY --diff` показывает разницу по шагам, файлам и критериям.

После утверждения `decide` работает по-прежнему: переоткрывает выполненные вехи и
добавляет решение в контекст остальных. План процесса проекта (ADR 0015) продолжает
свою сессию с ответом.

## Отвергнутые варианты

- **Продолжить сессию планировщика (`--resume`).** Она несёт всё прочитанное при первом
  планировании и стоит дороже новой сессии с планом в промпте; так уже сделаны правки по
  замечаниям проверки плана.
- **Проверять заново весь план.** Нетронутые вехи уже проверены; повторная проверка
  платит за них второй раз и может вернуть новые замечания к тому, что владелец не менял.
- **Править шаги вех без модели.** Friday не знает, какие шаги решение отменяет.

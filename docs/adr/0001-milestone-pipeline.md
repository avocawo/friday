# Конвейер по вехам вместо трёх проверок на каждом этапе

Пилот на фронтенд-проекте (задачи A и B) показал: на разработку ушло 21–32% запусков моделей, остальное — проверки. Каждая проверка читала дифф всей задачи, а любое решение владельца переоткрывало все закрытые этапы (разбор — `docs/process-redesign.md`). Поэтому ядро Friday пересобираем вокруг одной схемы:

план сильной моделью → проверка плана сильной моделью другого вендора → утверждение владельцем → исполнение по вехам (этап = коммит, веха = 2–5 этапов) → гейт в конце вехи → ревью вехи по диффу вехи → финальное ревью со слепой проверкой кода → черновой MR.

Браузерная приёмка идёт только на вехах с поведенческими критериями. Владелец участвует в двух точках: утверждает план и принимает черновой MR. Между ними конвейер не останавливается: находки, по которым исполнитель и ревьюер не сошлись, записываются в журнал как спорные, и владелец разбирает их на MR. Старые команды (`home-stretch`, `long-weekend`, `keep-watch` и другие) удаляются вместе со старым ядром, без слоя совместимости.

## Considered Options

- **Чинить текущее ядро точечно.** Отклонено: большая часть кода охраняет инварианты пошаговой схемы — переоткрытие этапов, три обязательные роли, привязку доказательств к каждому этапу. Улучшения поверх неё сохраняют сложность.
- **Три независимые роли на каждом этапе (прежнее поведение).** Отклонено как умолчание: в задаче B 29% проверок закончились `unverifiable`, то есть без результата. Слепая проверка кода остаётся, но только в финале.

## Consequences

- Этап перестаёт быть единицей ревью. Дефект, найденный на ревью вехи, исправляется в той же вехе, и закрытые этапы не переоткрываются.
- Решение владельца или замена плана переоткрывают только вехи, чьи файлы или критерии пересекаются с изменением. Если пересечение не доказано, переоткрывается всё, как раньше.

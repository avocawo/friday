# Потоки: независимые ветви плана идут параллельно

Параллельные вехи сейчас идут группой не больше двух, и сводятся только когда
закончится вся группа (`run_parallel` в `friday/milestone.py`).

Решение: поток — цепочка вех одной ветви графа `depends_on`, со своей рабочей копией и
веткой от ветки задачи. Потоки выводит Friday: веха продолжает поток своей
единственной зависимости; веха с несколькими зависимостями (точка сведения) начинает
новый поток после сведения всех зависимостей. Поле плана `parallel` больше не нужно.

- Потоки стартуют только после утверждённого плана (ADR 0014).
- Внутри потока строго по порядку: следующая веха ждёт ревью и сведения предыдущей.
- Готовая веха сразу сводится в ветку задачи переносом коммитов под блокировкой ветки.
- Пересечение файлов проверяется по `files` плана до запуска и по фактическим
  изменениям при сведении. Пересечение или конфликт останавливает только свой поток:
  рабочая копия сохраняется, вопрос уходит владельцу, остальные потоки идут дальше.
- Финальный гейт и финальные проверки — по сведённой ветке задачи.
- По умолчанию один MR задачи; `stream_delivery: "per-stream"` даёт MR на поток и
  отдельный MR на точку сведения.
- В режиме инструментов проекта (ADR 0015) поток — подграф этапов плана проекта, его
  исполняет отдельная сессия исполнителя проекта. Если команда исполнения проекта не
  принимает список этапов, потоки в этом режиме выключены.

## Considered Options

- **Группы с общей остановкой** — полосы простаивают на самой долгой вехе группы.
- **Поле `stream` от планировщика** — дублирует граф и может ему противоречить.
- **Отдельная задача Friday на каждый кусок** — деление и сведение остаются на
  владельце, финальное ревью не видит задачу целиком.

## Состояние

Не реализовано. В режиме инструментов проекта потоки выключены, пока команда исполнения
проекта не принимает список этапов.

## Решения владельца

1. Сводить по вехам: конфликт виден сразу, а остальные потоки строятся на сведённом коде.

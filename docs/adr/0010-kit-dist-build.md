# dist кита собирает владелец командой `friday dist` в контейнере проекта

В vue-uikit собранный `dist` лежит в репозитории и коммитится отдельным коммитом «<KEY>: Собран dist». В DVIZHDEV-7738 Friday об этом не знал: dist собирали вручную, ушло три пересборки. Правильная процедура описана в `docs/UIKIT_DOCKER_DEV.md` nfront. Кит собирается в контейнере dev-стенда nfront, из checkout `deps/vue-uikit`, который этот контейнер монтирует. В этом окружении `master` кита пересобирается байт в байт, кроме путей `__file`.

**Команда, а не шаг конвейера.** `friday dist KEY` запускает владелец. Сборка временно переключает чужой checkout `deps/vue-uikit` и делает `npm ci` в работающем контейнере владельца, а dev-стенд nfront по HMR сразу показывает кит из ветки задачи. Делать это молча посреди конвейера нельзя. Конвейер только отмечает, что dist нужен. У задачи профиля с блоком `dist` после всех вех стоит `dist: pending`. `friday status` и текст MR пишут «dist не собран: `friday dist KEY`», пока команда не выполнена.

**Процедура.** Профиль задаёт `dist.checkout` (путь к `deps/vue-uikit`, от файла профиля) и `dist.container`. Остальное по умолчанию повторяет процедуру nfront: `container_path` `/app/deps/vue-uikit`, `env` `NODE_ENV=development`, `install` `npm ci --prefix {path}`, `build` `npm --prefix {path} run build`, `cleanup` `node_modules/vue` и `node_modules/@vue`, `output` `dist`, `message` `{key}: Собран dist`. Команда:
1. Отказывается работать, если в checkout или в рабочей копии задачи есть незакоммиченные изменения или контейнер не запущен.
2. Запоминает, где стоит checkout (ветку или коммит), предупреждает про HMR и переключает checkout на коммит задачи (`--detach`: ветка задачи занята её рабочей копией).
3. В контейнере выполняет `npm ci`, затем сборку, затем удаляет вложенные `vue` и `@vue`. Именно после сборки: если удалить их до неё, `vue-tsc` кита возьмёт `@vue/language-core` из nfront, и `build:types` упадёт. Без удаления в dev-стенде nfront окажутся две Vue. Удаляет их сам контейнер, потому что файлы `npm ci` принадлежат его пользователю.
4. Копирует `dist` в рабочую копию задачи и коммитит его.
5. При любом исходе возвращает checkout: сначала `git checkout -- dist`, потом прежний ref. Если вернуть не удалось, печатает две команды, которыми это сделать вручную.

В отчёте — статистика нового коммита и прошлые коммиты «Собран dist» базовой ветки. Большой дифф `vue-uikit.es.js` при новом компоненте или импорте — переименования минификатора: его сравнивают с прошлыми сборками, а не пытаются уменьшить. `--check-base` собирает `origin/<base_branch>` так же и проверяет, что закоммиченный dist воспроизводится, без строк с `__file`. `--dry-run` только печатает шаги.

## Considered Options

- **Шаг конвейера перед доставкой.** Отклонено: шаг переключал бы общий checkout и ставил зависимости в чужом работающем контейнере без ведома владельца.
- **Сборка в рабочей копии задачи или в gate-образе.** Отклонено: dist должен совпадать с тем, что собирает nfront, а там сборка опирается на Vue и окружение контейнера nfront. Совпадение байт в байт проверено только для этой процедуры.

## Consequences

- Пока идёт сборка, dev-стенд nfront показывает кит из коммита задачи. После неё checkout возвращается, но `node_modules` кита остаются такими, какими их поставил `npm ci`.
- Карточка помнит, из какого коммита собран dist (`dist.source`). Если после сборки в ветку пришли новые коммиты, dist нужно собрать заново: сейчас Friday этого сам не замечает.

# Журнал в Obsidian собирается из событий по шаблонам Friday

Владелец читает ход работы в Obsidian, а не в карточке. Журнал задачи собирается по шаблонам Friday (`templates/`):
- Friday сам заполняет фактическую часть из событий карточки: вехи, коммиты, модели, время, стоимость, вердикты, ссылку на MR;
- агенты пишут только в отведённые поля: что сделано и почему, какие решения приняты;
- раздел «Спорные находки»: находка, кто её дал, ответ исполнителя с цитатой правила, статус «на решение владельцу».

Страница «Friday — сейчас» показывает все активные задачи со ссылками на их журналы.

## Considered Options

- **Журнал целиком пишут агенты.** Отклонено: это дороже и ненадёжно. Цифры и статусы должны совпадать с карточкой, а это гарантирует только детерминированная сборка.

## Consequences

- Каждый запуск модели должен сохранять расход (`usage`, стоимость, длительность) — без этого журналу нечего показывать.

# Кит показывается во внешнем Storybook, браузер сверяет его с макетом числами

После [ADR 0007](0007-design-tools.md) план vue-uikit знает макет, но для кита браузерная приёмка пропускалась (`browser_skipped`): у кита нет страницы, которую можно открыть. В DVIZHDEV-7738 семь браузерных критериев остались непроверенными. Код стенда в кит не добавляем: компоненты показывает отдельный репозиторий `vue-uikit-storybook`. В нём исходники кита лежат в `deps/vue-uikit` (игнорируется git), а `npm run link:uikit` подменяет пакет `@frontend/vue-uikit` ссылкой на них.

**Одна задача — две рабочие копии.** Профиль получает блок `stories` (репозиторий Storybook, базовая ветка, корень рабочих копий, `mount`, `setup`, `commands`, `image`). `start` создаёт рабочую копию Storybook на ветке задачи и рабочую копию кита внутри неё по пути `mount`, тоже на ветке задачи. Это штатная раскладка самого репозитория Storybook. Основным репозиторием задачи остаётся кит: gate, база, ревью вех и финал работают на нём. Файлы Storybook в плане пишутся с префиксом `stories:`, проверки выполнимости ищут их в Storybook. Исполнитель видит Storybook через `--add-dir`, пишет туда с разрешения песочницы и коммитит командами `git -C ../..`; коммит в одном Storybook тоже считается прогрессом вехи. Планировщик и ревьюеры читают обе копии, ревью получает оба диффа. Итог — две ветки задачи; при `delivery: none` Friday их не пушит.

**Preview — Storybook в образе самого репозитория.** Образ собирается из `Dockerfile` репозитория Storybook. ~~Собирает его владелец командой `friday image build`~~ — заменено [ADR 0011](0011-profile-steps.md): как собрать образ и как проверить его свежесть, профиль описывает шагом. Бэкенд `storybook`:
- запускает контейнер без сети и read-only;
- монтирует снимок HEAD Storybook в `/src`, а снимок HEAD кита — в `/src/<mount>`;
- кладёт в tmpfs каталоги из профиля и даёт команде профиля создать ссылку пакета кита на `/src/<mount>` (пример — профиль vue-uikit: `@frontend/vue-uikit`); это то, что `link:uikit` делает при запуске;
- запускает команду из `preview.command` профиля (с [ADR 0011](0011-profile-steps.md) команда, порт, окружение и пути — в профиле, а не в коде).

Мост на свободном порту и Chrome на 9333 в изолированном контексте не меняются. Браузерная роль открывает историю прямой ссылкой `iframe.html?id=<story-id>&viewMode=story`.

**Сверка с макетом.** При планировании Friday сохраняет `get_screenshot` каждого фрейма из тикета в папку задачи. Браузерная роль получает эти PNG и одобренную спецификацию `design`, а также инструменты `hover` и `computed_style(uid, properties)`. Второй — инструмент Friday: вычисленный CSS элемента через фиксированный скрипт, `evaluate_script` агенту по-прежнему не дан. Расхождение замера с пунктом спецификации блокирует и уходит исполнителю. Расхождение, видное только на глаз, в том числе композиция «элементы в рамке», — minor: оно уходит владельцу в MR и журнал.

**Темы.** `stories.themes` (для vue-uikit — `light` и `dark`) задаёт темы, а `stories.theme_query` — параметр URL (`globals=theme:{theme}`: addon-themes Storybook ставит `data-theme` на `<html>`, как хост). Браузерная роль открывает каждую историю в каждой теме. Сначала она убеждается, что тема применилась, затем сравнивает состояния компонента между собой: покой, hover, focus, active или перетаскивание, disabled. Каждое состояние должно заметно отличаться от покоя и делать элемент заметнее, а не тише. Так ловится дефект FileDropzone из DVIZHDEV-7738: в тёмной теме `--color-surface-hover` выходил темнее полупрозрачного `--color-surface`, и область при наведении гасла. Критерии приходят с префиксом `[<тема>]`. Friday сводит их в результат по каждой теме в событии `browser_checked`. Если хотя бы одна тема осталась непроверенной, браузерная приёмка вехи считается непроверенной ([ADR 0009](0009-unverified-is-not-done.md)).

**Проверка исполнителя для Storybook** — `npm --prefix ../.. run build`, то есть сборка Storybook при активном линке. Своих линта и типов в репозитории Storybook нет, а сборка ловит сломанные импорты историй. На хосте линк делает `stories.setup`: копирует `node_modules` Storybook и ставит ссылку на `deps/vue-uikit`.

## Considered Options

- **Постоянный playground в ките.** Отклонено владельцем: код стенда не должен попадать в кит.
- **Две рабочие копии рядом, а не вложенные.** Отклонено: вложенность — штатная схема репозитория Storybook. `.storybook/main.ts` сам ищет исходники в `deps/vue-uikit`.
- **Свой образ Friday для Storybook.** Отклонено: у репозитория есть свой Dockerfile, а Friday добавляет только ссылку при запуске.
- **Две связанные задачи Friday, кит и Storybook.** Отклонено: находки браузера пришлось бы возвращать из одной задачи в другую.

- Кит лежит внутри Storybook, поэтому Claude Code и Codex находят `CLAUDE.md` и `AGENTS.md` Storybook при поиске вверх от рабочей копии кита. Их видят все роли, работающие в ките, а не только планировщик; `--restricted` этого не отключает. Это лишние токены и чужие правила в каждой роли.
- Проверено вживую: исполнитель Claude Code в песочнице пишет и коммитит в обоих репозиториях (кит — в cwd, Storybook — через `--add-dir` и `git -C ../..`), без отказов. Кроме того, вживую работают мост и `computed_style` в Chrome 9333. Остальное покрыто тестами с фейками.
- Проверено вживую на образе `vue-uikit-storybook:friday` (кит и Storybook на `origin/master`): Storybook стартует из снимка без `.git` за секунды. `python3` для моста в образе есть. Импорты кита идут из `deps/vue-uikit/src`, а его зависимости находятся через `node_modules` Storybook. История `iframe.html?id=controls-button--primary` открывается в Chrome 9333 через мост, а `computed_style` видит стили кита: высоты 24 и 28 px, радиус 8 px.
- HMR и канал Storybook работают по WebSocket, а мост умеет только GET, поэтому в консоли страницы есть ошибки соединения. На отрисовку истории это не влияет, а консоль браузерная роль не читает. Правки исходников в открытой странице сами не появятся: preview показывает снимок коммита.
- На Codex `--add-dir` вживую не проверен.

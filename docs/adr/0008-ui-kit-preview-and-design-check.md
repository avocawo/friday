# Кит показывается в playground, браузер сверяет его с макетом числами

После [ADR 0007](0007-design-tools.md) план vue-uikit знает макет, но для кита браузерная приёмка пропускалась (`browser_skipped`): в профиле не было `preview`. В DVIZHDEV-7738 семь браузерных критериев остались непроверенными. Причин три. У кита нет страницы, которую можно открыть. Бэкенд `docker-vite` знал только корневой `vite.config.ts` и требовал стенд API. vue-uikit наследовал от nfront стейдж-авторизацию.

**Стенд кита — постоянный playground.** В master vue-uikit один раз появляются `playground/` и `vite.playground.config.ts` с реестром демо `src/**/*.demo.vue`; это отдельный MR в кит. UI-веха добавляет только демо своего компонента со всеми состояниями из макета; правило лежит в `engineering_policy` профиля. Пока конфигурации нет в базовой ветке, `doctor` предупреждает `preview_vite_config`.

**Preview без API.** `preview.vite_config` запускает Vite с этой конфигурацией. При `browser.mode: local` адрес API не передаётся, а `stage_origin`/`auth` запрещены. Остальное как раньше. Vite работает в gate-образе с Linux-сборками `node_modules`, без сети, на снимке HEAD; мост открывается на свободном порту `preview-<hex>.localhost`, браузер — общий Chrome на 9333 в изолированном контексте. На хосте `npm ci` не нужен, и `node_modules` gate не ломаются.

**Сверка с макетом.** При планировании Friday сохраняет `get_screenshot` каждого фрейма из тикета (`design/figma-<node>.png` в папке задачи). Браузерная роль получает эти PNG в рабочую папку, а в промпт — одобренную спецификацию `design`. У неё два новых инструмента: `hover` из chrome-devtools-mcp и `computed_style(uid, properties)`. Второй — инструмент Friday: вычисленный CSS элемента и его размер через фиксированный скрипт; `evaluate_script` агенту по-прежнему не дан. Расхождение замера с пунктом спецификации блокирует и уходит исполнителю. Расхождение, видное только на глаз, в том числе композиция «элементы в рамке», — minor: оно уходит владельцу в раздел «Мелкие замечания» MR и не гоняет исполнителя.

## Considered Options

- **Playground в каждой задаче.** Отклонено: каждая задача тратит этап на стенд, и стенды расходятся.
- **Storybook в ките.** Отклонено: тяжелее, а для приёмки достаточно страницы демо.
- **Dev-сервер на хосте с отдельными `node_modules`.** Отклонено: это второй `npm ci` на задачу и сеть на хосте, а контейнерный бэкенд уже решает проблему.
- **Все дизайн-находки minor.** Отклонено владельцем: числа из одобренной спецификации проверяемы, их расхождение — дефект.

## Consequences

- Для приёмки vue-uikit нужен разовый MR с playground в master кита; до него `doctor` предупреждает, а preview UI-вехи падает с `preview_unavailable`.
- Проверено вживую на рабочей копии DVIZHDEV-7738: preview отдаёт playground, Vue и Tailwind собираются в контейнере, `computed_style` читает стили в Chrome 9333. Полный прогон браузерной роли с моделью ещё не делался.

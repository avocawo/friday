# Работы и общий пул работников

Путь вехи сейчас — одна функция в одном потоке (`run` в `friday/milestone.py`): пока
идёт ревью, полоса занята, хотя исполнитель ей уже не нужен.

Решение: путь вехи режется на работы, у каждой своя роль. Один пул работников на
машину берёт любую готовую работу любой задачи и любого потока (ADR 0013).

## Порядок задачи

1. План и все его проверки заканчиваются до первой работы исполнения.
2. Пока владелец не утвердил план (`friday approve`), работы задачи в очередь не
   попадают; `approval: auto` с пулом не действует.
3. Если у проекта есть своё средство для фазы (ADR 0015), фаза идёт им, а не ролью
   Friday.

## Работы

| Работа | Роль | Что держит |
|---|---|---|
| исполнение вехи, правки по ревью | `develop` | рабочую копию потока, единственный писатель |
| гейт | — | слот `gate`, снимок коммита |
| ревью вехи | `review` | worktree на проверяемом коммите, только чтение |
| браузер | `browser` | слот `browser`, стенд |
| финальное ревью, слепая проверка | `final-review`, `blind-code` | сведённую ветку задачи |

- Внутри потока строго по порядку, опережающего исполнения нет.
- Работник берёт работу, если свободны её слоты (`machine.json`) и есть модель роли с
  учётом квот.

## Пул

- Размер — `max_workers` машины; одна задача занимает не больше
  `max_workers_per_task` (по умолчанию половина пула).
- Очередь держит постоянный процесс `friday serve`; `approve`, `resume`, `decide`,
  `stop` работают с его очередью. После сбоя он восстанавливает очередь из карточек.
- `friday service install` ставит агент launchd (macOS) или юнит systemd (Linux) с
  явными путями к `claude`, `codex`, `docker`, `git`.
- Friday работает на хосте; Docker — только для гейта и превью.

## Несколько задач одного репозитория

- Проверка, которую запускает исполнитель проекта (ADR 0015), идёт его средствами в
  своей рабочей копии; решает изолированный гейт Friday по коммиту после сессии.
- Образ гейта и превью собирается под lock-файл шагом профиля, который запускает
  владелец (ADR 0011). Если lock-файл задачи не совпадает с образом, её поток
  останавливается вопросом с командой шага; сам конвейер образ не собирает: сборка на
  хосте с секретами реестра без владельца — то, от чего уходил ADR 0011.
  Сделано: гейт отличает такой образ (`image_stale`) от сбоя окружения, задача
  останавливается с полем `owner_step` и командой шага из `gate_image_step`. Это не
  вопрос сессии исполнения: `resume` после шага повторяет только проверки.
- Пересечение файлов с другой активной задачей (`plan.overlaps`) — вопрос владельцу при
  утверждении: параллельно, после неё или поверх её ветки. Ответ становится
  зависимостью в очереди.
- `fetch`, создание и удаление рабочих копий и веток, сведение — под блокировкой
  `repo:<путь>`.
- Слоты `machine.json` задают, сколько проверок и браузеров окружение проекта
  выдерживает одновременно.

## Вопросы владельцу

Развилка решения, факт кода против плана, спорное замечание ревью, исчерпанные круги
правок — останавливают только свой поток. Вопрос уходит владельцу сразу, с базой и
предложенным решением; поток продолжается после `friday decide`. Спорные замечания до
MR больше не копятся.

В режиме ADR 0015 поток — одна сессия исполнителя проекта; вопрос завершает сессию, а
после решения она продолжается через `--resume`.

## Considered Options

- **Опережающее исполнение внутри потока** — правка по ревью пересобирает следующую
  веху.
- **Пул на задачу** — свободная мощность одной задачи не помогает другой.
- **Friday в Docker на Mac** — нужен сокет Docker хоста и пути один в один, нет
  Keychain для подписки Claude Code.
- **Спорное — вместе с MR** — неверное решение успевает разойтись по потокам.

## Consequences

- Состояние в карточке — на уровне работы, а не вехи; это главная переделка
  `run_task` и `resume`.
- Сбой `friday serve` останавливает все задачи машины до перезапуска.

## Решения владельца

1. Приоритет — по времени утверждения плана; работа, продолженная после `friday decide`,
   идёт первой. Отдельного поля приоритета нет.
2. Вопрос владельцу — в `status`, журнале и системным уведомлением: при фоновом
   `friday serve` вопрос без уведомления никто не увидит.

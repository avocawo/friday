# Макет Figma читает план, /impeccable приходит текстом в промпт

В задаче DVIZHDEV-7738 (FileDropzone в vue-uikit) план, исполнение и ревью прошли, но ни одна роль не открыла Figma. Компонент не совпал с фреймом по иконке, высоте, скруглению, hover и Focus/Active, и дизайн-проход пришлось делать вручную вне Friday. Теперь профиль включает дизайн-инструменты ключом `design`.

**Figma.** Ссылку на фрейм Friday берёт из тикета (`figma.com/design/<file>/…?node-id=…`). До планирования он проверяет локальный Dev Mode MCP-сервер Figma desktop (`127.0.0.1:3845`): каждый узел из тикета должен находиться через `get_metadata`. Живой доступ к Figma получают только `plan` и `plan-review`, и только к инструментам чтения: `get_metadata`, `get_design_context`, `get_screenshot`, `get_variable_defs`. Планировщик выносит из фрейма измеримую спецификацию в поле плана `design`: размеры, отступы, скругления, иконки, токены, состояния. Её же он превращает в критерии этапов. Владелец одобряет спецификацию вместе с планом. `develop`, `review` и `final-review` получают одобренную спецификацию в промпте, без MCP. `blind-code` её не получает: он слепой по контракту.

**/impeccable.** Скилл не запускается внутри роли. Вместо этого Friday читает выбранные файлы `reference/` из закреплённой папки скилла и кладёт их в промпт ролей, работающих с UI-вехами. По умолчанию `develop` получает `craft-floor.md` и `polish.md`, а `review` и `final-review` — `component-review.md`. Блок стоит перед данными вехи, поэтому совпадает у всех вех и попадает в кэш промпта.

**Figma недоступна — задача ждёт владельца.** Если сервер не отвечает или узла нет в активной вкладке Figma, `start` останавливается с ошибкой `design_unavailable` и говорит, что сделать: запустить Figma, войти, открыть файл. Владелец исправляет причину и повторяет `start`. `start --no-design` планирует без макета; это записывается событием `design_skipped`. Тихий пропуск макета и привёл к DocumentMaster.

## Considered Options

- **Вызывать скилл `/impeccable` из роли.** Отклонено. Роли запускаются с `--restricted` и узким `--tools`, инструмента `Skill` у них нет. `--restricted` не читает пользовательские настройки, поэтому установленные плагины не включены. `--plugin-dir` включил бы и хуки плагина. Первый шаг скилла запускает бинарник через Bash и при первом запуске качает его из сети. У ревьюеров Bash нет, у исполнителя песочница без сети, и `~/.claude` закрыт для чтения. Сам скилл на этот случай предлагает читать контекст напрямую, и Friday делает это за роль.
- **Figma живьём у всех ролей.** Отклонено. Инструменты desktop-сервера принимают только `nodeId`, без ключа файла, и читают активную вкладку Figma. За час исполнения владелец может переключить файл, и роль молча прочитает чужой узел. При планировании владелец за клавиатурой, а результат он одобряет.
- **Удалённый сервер Figma (`mcp.figma.com`, плагин `figma`).** Отклонено. Ему нужен интерактивный вход через OAuth, а в headless-запуске он невозможен.
- **Продолжать без макета и считать дизайн-критерии непроверяемыми.** Отклонено владельцем: именно тихий пропуск дал расхождение.

## Consequences

- `runner.Spec.mcp` принимает список серверов: у каждого stdio-`command` или `url`. План может одновременно держать graphify и Figma. Флаги `--restricted --strict-mcp-config --no-chrome` не меняются. Разрешены только перечисленные инструменты, пишущие инструменты Figma (`add_code_connect_map`, `send_code_connect_mappings`) профиль не принимает. MCP-соединение держит процесс `claude`, а не shell в песочнице, поэтому loopback-адрес Figma не открывает сеть для Bash.
- Для Codex HTTP-сервер передаётся ключом `mcp_servers.<name>.url`; это проверено только тестом с фейком, не вживую.
- План с фреймами в тикете без спецификации `design` не проходит проверку выполнимости и уходит планировщику на доработку.
- Перед `start` в Figma должна быть открыта нужная вкладка. Friday проверяет, что узел существует, но не может проверить ключ файла: сервер его не сообщает.
- Расход: примерно 3 тыс. токенов на сессию исполнителя UI-вехи и 2 тыс. на ревью.
- Пересматривает строку «Субагенты, skills, output styles — не нужно» в `docs/research/orchestrator-practices.md`. Скилл как рантайм внутри роли по-прежнему не нужен, а его reference как текст в промпте нужен.
- Не решено. Цельность композиции по диффу не проверить: нужен отрендеренный компонент рядом со скриншотом макета. Для vue-uikit это значит `preview` и браузерная приёмка со сравнением с макетом; это отдельный шаг.

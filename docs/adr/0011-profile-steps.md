# Сборки и другие проектные процедуры — шаги профиля, а не команды Friday

После ADR 0008 и 0010 в Friday появились две команды, знающие устройство одного проекта. `friday image build` собирала образ витрины: BuildKit-секрет, `--add-host`, `git archive` базовой ветки, метка lockfile. `friday dist` повторяла процедуру сборки dist одного UI-кита в контейнере его хост-проекта: пути внутри контейнера, переменные окружения, удаление вложенных пакетов, текст коммита. Кроме того, в коде лежали значения по умолчанию одного проекта: путь кита в витрине, команда запуска Storybook с путями `node_modules`, имя пакета, файлы /impeccable. Владелец решил, что Friday не знает конкретных проектов и способов их сборки. Всё проектное указывается в профиле.

**Шаг профиля.** Профиль описывает шаги в `steps`, Friday умеет общие вещи: выполнить шаг, проверить его готовность, показать результат и напомнить о невыполненном. Пример — с вымышленными именами:

```json
"steps": {
  "bundle": {"scope": "task", "when": "owner", "required": true,
             "run": ["{profile_dir}/build-bundle.sh", "{worktree}", "{head}"],
             "commit": {"paths": ["dist"], "message": "{key}: build dist"}},
  "preview-image": {"scope": "profile", "when": "owner",
                    "run": ["{profile_dir}/image.sh", "build", "{secret.registry}"],
                    "check": ["{profile_dir}/image.sh", "check"],
                    "secrets": {"registry": "~/.npmrc"}}
}
```

- `run` — массив аргументов, без shell. Подстановки зависят от `scope`. У шага задачи это `{key}`, `{worktree}`, `{branch}`, `{base}`, `{head}`, `{showcase}`. У любого шага — `{profile_dir}`, `{repository}`, `{base_branch}`, `{stories_repository}` и `{secret.<имя>}`. Подстановку, которой у шага нет, профиль не пройдёт.
- `container` выполняет команду через `docker exec` в этом контейнере; `env` и `cwd` — как обычно.
- `when: owner` — шаг запускает только владелец командой `friday step NAME [KEY] [--profile P]`, конвейер его не трогает. Так помечаются шаги, которые трогают чужой checkout или работающие контейнеры хоста. `when: before_delivery` — конвейер выполняет шаг сам, перед доставкой.
- `required` (шаг задачи) — пока шаг не выполнен, `friday status`, журнал и текст MR пишут «Шаг не выполнен» с командой. Список обязательных шагов попадает в карточку до того, как пишется текст MR.
- `commit` — после успешного шага Friday коммитит в ветку задачи только перечисленные пути с сообщением из профиля. Если рабочая копия не чистая, шаг не запускается.
- `check` (шаг профиля) — команда готовности для `doctor`: код 0 — готово, 2 — устарело (предупреждение), любой другой — нет (✗). Последняя строка вывода — причина, к ней Friday добавляет команду запуска шага.
- `secrets` — файлы, которые команда получает путём. Friday только проверяет, что файл есть, и никогда его не открывает.
- `friday step … --dry-run` печатает команду с подстановками и ничего не запускает.

Процедуру длиннее одной команды профиль кладёт скриптом рядом с собой, вне репозитория Friday. Восстановление чужого checkout при ошибке — тоже забота такого скрипта.

**Без проектных значений по умолчанию.** Обязательными стали поля, у которых раньше были проектные значения по умолчанию: `stories.mount`, `stories.theme_query` (при `themes`), `design.impeccable.references`. У бэкенда preview `storybook` в профиле указываются `command` (`{mount}` — путь кита), `port`, `env`, `tmpfs` и `links`. Ошибка профиля называет недостающее поле.

## Considered Options

- **Оставить проектные команды и вынести только значения в профиль.** Отклонено: способ сборки — это последовательность действий, а не набор параметров. Каждый новый проект потребовал бы новых ключей и веток в коде.
- **Скрипты в репозитории Friday.** Отклонено: это то же проектное знание, только в другом файле.

## Consequences

- Команд `friday image` и `friday dist` больше нет; ADR 0010 и раздел про сборку образа в ADR 0008 заменены этим решением.
- Карточки, где dist отмечен старым способом (`dist`), напоминание не покажут; обязательные шаги появятся у них при следующем финале.
- Friday проверяет подстановки, коммит результата, проверку `doctor` и то, что секреты не открываются. Что делает сам скрипт, в том числе возвращает ли он чужой checkout при ошибке, Friday не проверяет: это ответственность профиля.

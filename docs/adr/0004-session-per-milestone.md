# Одна сессия исполнителя на веху, параллельно — только вехи без общих файлов

Рассматривались три варианта. Одна длинная сессия на всю задачу теряет детали при сжатии контекста. Параллельные сессии на каждый этап почти ничего не дают: в пилоте этапы шли цепочкой (типы → репозиторий → стор → виджет → страница), а каждая сессия заново собирает контекст. Anthropic измерил, что для одной зависимой цепочки одна модель выигрывает у оркестратора с исполнителями, а мультиагентные схемы тратят около 15× токенов чата.

Выбрано: на каждую веху — своя сессия исполнителя. Она стартует с плана, брифа вехи и короткого итога предыдущих вех. Повторы после гейта и ревью продолжают ту же сессию, чтобы сохранить кэш и прочитанный контекст. Вехи, которые планировщик пометил как не пересекающиеся по файлам, идут параллельно в отдельных worktree и сливаются в ветку задачи по очереди.

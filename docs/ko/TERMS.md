# 한국어판 용어집

어조: 한국어 개발자 문서에서 일반적으로 쓰는 중립적인 기술 문서 문체(합니다체). 홍보성 표현은 쓰지 않는다. 정착된 외래어(리뷰, 파이프라인, 프로필, 워크트리)는 그대로 쓴다.

각 번역 파일에 넣을 번역 안내 문장:

_이 문서는 영어판 문서를 번역한 것입니다. 내용이 다를 경우 영어판이 우선합니다._

| English | 한국어 | Note |
| --- | --- | --- |
| task | 작업 | 영어를 병기하지 않는다. "태스크"는 쓰지 않는다. |
| plan | 계획 | 영어를 병기하지 않는다. "플랜"은 쓰지 않는다. |
| milestone | 마일스톤 | 영어를 병기하지 않는다. |
| stage | 단계 | 영어를 병기하지 않는다. 마일스톤과 구분하기 위해 "스테이지"는 쓰지 않는다. |
| criterion | 기준 | 복수형도 "기준". 인수 기준을 뜻한다. |
| profile | 프로필 | 영어를 병기하지 않는다. |
| owner | 오너 | "소유자", "사용자"는 쓰지 않는다. |
| planner | 플래너 | 모델의 역할 이름. 영어를 병기하지 않는다. |
| executor | 실행자 | 구현을 맡는 모델의 역할 이름. 영어를 병기하지 않는다. |
| reviewer | 리뷰어 | 영어를 병기하지 않는다. |
| model tier | 모델 등급 | 처음 한 번만 "모델 등급(model tier)"으로 영어를 병기한다. |
| role assignment | 역할 배정 | 처음 한 번만 영어를 병기한다. |
| gate | 게이트 | 처음 한 번만 "게이트(gate)"로 영어를 병기한다. 코드의 키 이름은 영어 그대로 둔다. |
| milestone review | 마일스톤 리뷰 | 영어를 병기하지 않는다. |
| final review | 최종 리뷰 | 영어를 병기하지 않는다. |
| blind check | 블라인드 검사 | 처음 한 번만 영어를 병기한다. |
| browser acceptance | 브라우저 인수 확인 | 처음 한 번만 영어를 병기한다. |
| disputed finding | 이견이 있는 지적 | 처음 한 번만 영어를 병기한다. |
| card | 카드 | 영어를 병기하지 않는다. |
| journal | 저널 | 영어를 병기하지 않는다. "일지"는 쓰지 않는다. |
| worktree | 워크트리 | Git 용어. 영어를 병기하지 않는다. |
| draft MR | 초안 MR | GitHub 한국어 표기에 맞춰 "초안"을 쓴다. MR은 약어 그대로 둔다. |
| pipeline | 파이프라인 | 영어를 병기하지 않는다. |
| vendor | 벤더 | 영어를 병기하지 않는다. |
| test environment | 테스트 환경 | 영어를 병기하지 않는다. |
| preview | 프리뷰 | 영어를 병기하지 않는다. |
| finding | 지적 | 리뷰에서 나온 지적 사항. "발견"은 쓰지 않는다. |
| verdict | 판정 | "평결"은 쓰지 않는다. |
| sandbox | 샌드박스 | 영어를 병기하지 않는다. |
| spending | 비용 | 누적 비용을 뜻한다. "지출"은 쓰지 않는다. |

# Исследование: механизмы для Friday

Дата: 28 октября 2026. Изучены первоисточники открытых инструментов; это ориентиры для проектирования, а не описание уже реализованных возможностей Friday.

- [DVC: описание этапов и `dvc.lock`](https://doc.dvc.org/user-guide/project-structure/dvcyaml-files) сохраняет определения этапов и сведения о зависимостях. Для Friday стоит проверять и состав гейта, и содержимое проверяемого дерева до и после запуска: одна успешная команда не доказывает, что код остался прежним.
- [Git: status](https://git-scm.com/docs/git-status) показывает разницу между HEAD, индексом и рабочим деревом, а также неотслеживаемые файлы. При расчёте отпечатка недостаточно сохранять только строки статуса: важно содержимое файлов и особенности индекса.
- [uv: безопасность кэша](https://github.com/astral-sh/uv/blob/main/docs/concepts/cache.md) описывает блокировку кэша при изменениях. Для Friday общие ресурсы нуждаются в раздельных блокировках, а аварийное завершение процесса не должно навсегда их захватить.
- [uv: конфигурация](https://docs.astral.sh/uv/concepts/configuration-files/) определяет поиск и приоритет конфигурации. В Friday потребуется явно описать расположение, выбор и проверку профиля, чтобы поведение не зависело от случайного рабочего каталога.
- [CrewAI: сохранение состояния](https://github.com/crewAIInc/crewAI/blob/main/lib/crewai/src/crewai/flow/persistence/sqlite.py) хранит состояние потока и контекст ожидаемого решения. Friday тоже должен сохранять решение и процесс так, чтобы после остановки можно было понять, что осталось выполнить; это не предписывает конкретное хранилище.
- [LangChain: решение человека](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/human-in-the-loop.mdx) описывает приостановку и утверждение конкретных действий. В Friday разовое разрешение должно быть связано с конкретным содержимым действия и версией кода и переставать действовать после их изменения.
- [OpenHands: CLI](https://github.com/OpenHands/docs/blob/main/openhands/usage/cli/command-reference.mdx) документирует машиночитаемый вывод и коды завершения. Для Friday фиксируем явный формат ответа и проверяем его через вызов настоящей команды.
- [Claude Code: CLI](https://code.claude.com/docs/en/cli-usage) описывает неинтерактивный вывод, JSON Schema и ограниченный режим; [Z.ai: Claude Code](https://docs.z.ai/devpack/tool/claude) — подключение GLM Coding Plan через отдельный endpoint. Friday использует отдельный процесс и окружение для каждого поставщика. Синтетические вызовы Claude и GLM прошли; ограничения CLI для рабочих задач ещё не подтверждены.
- [OpenAI: Multi-agent](https://developers.openai.com/api/docs/guides/responses-multi-agent) описывает выбор подзадач моделью и лимит параллельных исполнителей. В Friday предложенную моделью команду проверяет собственный диспетчер; текущая реализация выполняет её последовательно.

Открытые вопросы перед реализацией соответствующих этапов: точная граница содержимого отпечатка; поддерживаемые файловые системы и семантика блокировки; схема миграций карточки; модель идентификации разрешаемого действия. До решения этих вопросов выводы выше не являются гарантиями Friday.

# Friday

[English](../../GLOSSARY.md) · [Русский](../ru/GLOSSARY.md) · **简体中文** · [日本語](../ja/GLOSSARY.md) · [한국어](../ko/GLOSSARY.md) · [Português (Brasil)](../pt-br/GLOSSARY.md) · [Español](../es/GLOSSARY.md) · [Deutsch](../de/GLOSSARY.md) · [Français](../fr/GLOSSARY.md) · [Bahasa Indonesia](../id/GLOSSARY.md)

*本文是英文文档的译文；如与英文版有出入，以英文版为准。*

一条个人开发流水线：借助来自不同厂商的模型，把任务从计划推进到草稿 MR，并检查它们的工作。

## 工作

**任务**：
负责人的一个工作单元，有自己的任务卡、分支和 worktree；通常对应一张 tracker 工单。
_Avoid_: 作业, 工作项

**计划**：
一个任务的里程碑和阶段列表，附带验收标准，由负责人批准。

**里程碑**：
由 2–5 个连续阶段组成的一组，作为整体通过关卡和评审。
_Avoid_: 版本, 节点

**阶段**：
计划中最小的部分；以一次提交结束。
_Avoid_: 子任务, 小步

**验收标准**：
对某个阶段可验证的验收条件；要么是代码验收标准（对照 diff 检查），要么是行为验收标准（在浏览器中观察）。

**配置文件**：
为单个项目配置 Friday 的 JSON 文件（仓库、模型、角色、关卡、浏览器、tracker、日志、交付）；可以通过 `extends` 键扩展另一个配置文件。

## 角色

**负责人**：
批准计划、验收草稿 MR 并裁决有争议的发现的人。
_Avoid_: 管理员, 使用者

**规划模型**：
编写计划的模型。

**执行模型**：
编写某个里程碑代码的模型。
_Avoid_: 程序员, 编码员

**评审模型**：
评审计划、里程碑或最终 diff，并就验收标准给出结论的模型。

**模型档位**：
模型的能力等级：`frontier`、`strong` 或 `efficient`。

**角色分配**：
把具体模型分配给任务的各个角色，在计划获批之前固定下来。

## 检查

**关卡**：
不使用模型的确定性检查，在隔离的容器中针对某个特定提交运行。
_Avoid_: 持续集成, 校验

**里程碑评审**：
由不同厂商的评审模型对里程碑的 diff 和关卡日志进行评审。

**最终评审**：
在提交 MR 之前，对整个任务 diff 进行评审，包括对代码的盲审。

**浏览器验收**：
在本地测试环境的浏览器中，观察某个里程碑的行为验收标准。
_Avoid_: blind-behavior

**有争议的发现**：
执行模型不同意的评审发现，通过日志交给负责人处理。

## 记录

**任务卡**：
Friday 对任务的机器状态记录：事件、里程碑、结论、花费。

**日志**：
任务在 Obsidian 中的可读历史，由任务卡通过模板生成。
